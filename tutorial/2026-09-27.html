01

给 Claude Code 装一个"每日工作日志"：hooks + systemd + 私有 git 仓，数据永不出本机

AI Coding 发布 2026-09-26 🔥 值得马上实践 📌 值得收藏 ⭐⭐ 有基础用户可复现
一句话摘要：作者开源了 worklog-for-claude-code——自动汇总"今天用 Claude Code 做了什么、烧了多少 token"，跨多台电脑多个账号，全程本地 + 私有 git 仓同步。

原始教程

  • Blog 原帖asadqi.com — I built a daily work log for Claude Code, and it never leaves my machines
  • GitHubus-urvin/worklog-for-claude-code（0.1.0 首次公开发布于 2026-09-26，MIT）
  • PyPIworklog-for-claude-code

作者是谁

Adil Sadqi，独立开发者，日常工作重度使用 Claude Code（笔记本 + 台式机、工作 + 个人双账号）。这是他为自己痛点写的工具，属于典型第一手 Build Log。

教程讲了什么

作者每天 18 点回答不了两个问题：今天到底做完了什么？token 用了多少？他用 Claude Code 的 session hooks（会话开始/结束触发）读取本地 transcript，外加每小时 systemd 定时器兜底，把每次会话写成一条小 JSON 记录存进自己的 git 仓——每台设备只写自己的文件路径，多机推送同一仓库也不会冲突。夜间任务把记录聚合成 Markdown 报告，本地 Web UI 展示。隐私是第一设计约束：只存 prompt 前 300 字符、token 数、文件名和 commit 标题，落盘前脱敏 API key/JWT/邮箱/IP。

为什么值得收藏

这是"AI Coding 进入日常化之后"才会出现的工具：当 Claude Code 成为你的主要工作方式，可审计性（做了什么）和可计量性（用了多少）就变成刚需。它还示范了一套干净的本地工具架构：hooks + systemd + git 同步 + loopback Web UI，对企业里"AI 使用量统计但不能上传代码"的合规场景有直接参考价值。

技术栈

模型可选 AI 摘要走你自己的 claude -p（可关闭，关闭后完全无模型调用）
工具Claude Code hooks、systemd timer、git、本地 Web UI（loopback only，CSRF + 严格 CSP）
语言Python 3.10+（pipx 安装）
部署环境Linux + systemd（暂不支持 macOS/Windows）；数据可放私有 GitHub/GitLab 仓多机同步
其他MIT 协议；transcript 解析为非官方格式，解析器跳过无法识别的行而非崩溃

完整 Workflow

Claude Code 会话（本地 transcript 文件）
↓
采集双通道：Session hooks（开始/结束触发）＋ 每小时 systemd timer 兜底
↓
脱敏 & 裁剪：prompt 截 300 字符，移除 key/token/JWT/邮箱/IP（best effort）
↓
写入私有 git 仓：每次会话一条 JSON，按设备隔离文件路径，多机无冲突
↓
夜间聚合任务 → Markdown 日报（项目摘要 + 分账号/分模型 token + 14 天曲线）
↓
本地 Web UI（127.0.0.1，Host/Origin 校验）

手把手复现

  1. 30 秒体验（假数据、不碰你的文件）：pipx run --spec worklog-for-claude-code claude-worklog demo，打开 http://localhost:8766
  2. 正式安装：pipx install worklog-for-claude-code
  3. 建数据目录：git init ~/claude-worklog-data
  4. 装后台服务：claude-worklog install-service
  5. 打开 http://worklog.localhost:8765，填设置表单，点 Install hook
  6. 多机使用：把数据目录放进私有 GitHub/GitLab 仓库，各机器推送同一仓

关键代码 / 配置

pipx install worklog-for-claude-code
git init ~/claude-worklog-data
claude-worklog install-service
# 然后浏览器打开 http://worklog.localhost:8765 → Install hook

架构上最值得学的一点："每个文件路径只由一台设备写入"——用写入权划分取代锁和合并逻辑，多台机器可以向同一个 git 仓推送而永远不会产生 merge conflict。

踩坑与注意事项

⚠ 作者明示的限制：
  • 仅 Linux + systemd；macOS 需要有人贡献 launchd 单元
  • 只支持 Claude Code（claude.ai 网页聊天不落本地 transcript）
  • transcript 格式非官方，Claude Code 升级可能暂时打断解析
  • token ≠ 美元：Pro/Max 订阅按限额计，不显示价格
  • 脱敏是 best effort——数据仓务必保持私有

普通人能不能复现

⭐⭐ 有基础用户 会基本 Linux 命令行 + 用 pipx 即可，10 分钟装好；不需要写任何代码。

如何迁移到其他场景

① 团队 AI 用量看板同一架构聚合整个团队的 Cursor/Codex 使用日志，做部门级成本归因
② freelancer 工时证明按项目自动产出"做了什么"的日报，直接作为向客户报工时的附件
③ 个人复盘系统把"会话 JSON + 夜间聚合"模式迁移到任意工具链做个人数字足迹复盘

培训师点评

点评：真正值得教的不是这个工具本身，而是两个工程判断：① 用"写入权划分"消灭分布式冲突；② 把隐私当第一需求而不是事后补丁。AI 工具越深入工作流，这类"可审计 + 数据不出机"的设计越会成为企业采购的硬门槛。

亲手建一个 MCP Server 并接通 Claude Code / Codex / Cursor：180 行 Python、8 分钟跑通、6 个坑全记录

MCP 发布 2026-09-26 🔥 值得马上实践 🎓 值得培训 📌 值得收藏 ⭐⭐ 有基础用户可复现
一句话摘要：The Hype 团队当天建了一个真实 MCP Server（读自家站点文章），在三大 AI 客户端逐一实测连通，并公开了全部命令、6 次报错与修复、以及每次运行的实际 token 成本。

原始教程

  • Blog 原帖thehype.news — How to Build an MCP Server: A Tested 2026 Guide（作者 Addy Crezee，24 分钟阅读）

教程讲了什么

作者用官方 MCP Python SDK 2.2.0 建了一个名为 thehype 的 Server，180 行 Python 提供三个工具：latest_articles（读 RSS）、read_article（长文分段返回）、search_articles（走 Ghost Content API，演示带 key 的 API 包装）。随后用 MCP Inspector 测试，并逐一接入 Claude Code、Codex、Cursor，记录了从 uv init 到首个双工具版本在 Claude Code 和 Codex 中跑通仅 8 分钟，以及 6 个真实故障的报错与修法。

技术栈

模型Claude Opus 5.5（测试客户端侧）；Server 本身不调模型
工具MCP Python SDK 2.2.0、MCP Inspector、uv、Claude Code / Codex / Cursor
语言Python 3.10+（另附 TypeScript 版）
其他Node.js 22.19+（跑 Inspector）；单次测试成本约 $0.10–0.32（作者实测记录）

手把手复现

  1. 环境：Python 3.10+、uv、Node.js 22.19+
  2. 建项目：uv init thehype-mcp && cd thehype-mcp && uv add "mcp[cli]==2.2.0"
  3. 写 server.py：SDK 2.x 主类已从 FastMCP 更名为 MCPServer
  4. 工具参数描述用 Annotated[type, Field(description=..., ge=..., le=...)]
  5. Inspector 测试：npx @modelcontextprotocol/inspector --cli uv run server.py --method tools/list
  6. 接 Claude Code：claude mcp add thehype -- uv --directory /绝对路径/thehype-mcp run server.py
  7. 接 Codex：codex mcp add thehype -- ...；自动化运行时对只读工具单独设 approval_mode="approve"
  8. 接 Cursor：.cursor/mcp.json 必须放在 git 仓库根目录

关键代码 / 配置

// Cursor CLI 权限配置（.cursor/cli.json）——"deny": [] 省略会直接 schema 校验失败
{
  "permissions": {
    "allow": ["Mcp(thehype:latest_articles)", "Mcp(thehype:read_article)"],
    "deny": []
  }
}

长文工具的分段返回设计值得抄：文章超过 8000 字符时按 "Part N of M" 返回，并在工具描述里告诉模型可以请求下一段。

踩坑与注意事项

⚠ 作者实测的 6 个坑（含修复）：
  1. Inspector 吞掉 --directory 参数 → 报 Connection closed；改在项目目录内运行
  2. docstring Args 段不被 SDK 解析 → 参数描述全丢；改用 Annotated + Field
  3. read_article 截断 8000 字符 → 模型总结覆盖不全；改为 Part N of M 分页
  4. Codex 自动化运行拦截工具（approval never）→ 对只读工具逐个 approve
  5. Cursor 在嵌套 git 仓中完全读不到 .cursor/ 配置 → 放仓库根目录
  6. Cursor cli.json 缺 deny 字段 → schema validation failed；补空数组 + 精确白名单

普通人能不能复现

⭐⭐ 有基础用户 会 Python 基础 + 命令行即可；全文命令完整可复制，作者从建项目到跑通只用了 8 分钟。

培训师点评

点评：这篇教程的教学价值在"失败日志的完整性"——6 个坑每一个都有报错原文、根因和修法。教 MCP 最容易犯的错误是只讲协议美好的一面；这篇告诉你真正的工程量 80% 在客户端的权限与配置细节上。

Rig：给你的 Agent 配一台"小型操作系统"——单二进制、沙箱 Worker、cron 调度、模型可自写插件

AI Agent Show HN 2026-09-26 🧪 值得实验 ⚠ 二进制分发，未见公开源码仓 ⭐⭐ 有基础用户可复现
一句话摘要：一条 curl 装好的单文件 Agent 运行时：接任意 OpenAI 兼容端点，后台 Worker 跑长任务、cron 定时巡检、Python 插件即插即用，任务/记忆/会话全部落盘可随时恢复。

原始教程

  • Show HNShow HN: Rig, a small operating system for your agent（2026-09-26 发布；安装脚本域名 tryrig.ai）

教程讲了什么

Rig 把一个 OpenAI 兼容端点（本地 llama.cpp/Ollama 或 OpenRouter 等托管服务）变成能长期干活的 Agent。亮点设计：工具调用并行但结果按序落地；Worker 在沙箱（jail）里跑长任务且保留可恢复的 transcript；/scheduler 用真实 cron 表达式定时任务；插件就是一个含 DESCRIPTION/SCHEMA/run 的 Python 文件，模型自己写的插件会进 pending 目录等人工批准；所有状态（任务、记忆、调度、会话）都在仓库里落盘，可从手机 SSH 恢复会话。

技术栈

模型任意 OpenAI 兼容端点：llama.cpp、Ollama、OpenRouter 等
工具Rig 单二进制（签名发布、原地自更新）；插件为 Python 文件
部署环境Linux / macOS，amd64 / arm64，无 sudo 无依赖，装到 ~/.local/bin

手把手复现

  1. 安装：curl -fsSL https://tryrig.ai/install.sh | sh
  2. 写 ~/.rig/settings.json：指定 model 与 baseUrl
  3. 写 ~/.rig/models.json：每个模型一行——上下文窗口、maxTokens、reserve、effort 档位
  4. 写 ~/.rig/AGENTS.md 常驻指令
  5. 进项目目录运行 rig，试着说："熟悉一下仓库，后台跑全量测试，把学到的东西记下来"

关键代码 / 配置

# ~/.rig/plugins/weather.py —— 一个插件就只有这三样
DESCRIPTION = "current weather for a city"
SCHEMA = {"type": "object", "properties": {"city": {"type": "string"}}}

def run(args):
    return fetch_weather(args["city"])

模型自己也能写插件，但会落在 pending 目录——你批准之前它不会生效。这一条把"Agent 自我扩展能力"和"人对能力边界的控制"同时保住了。

踩坑与注意事项

⚠ 注意：
  • 当前为签名二进制分发，未观察到公开源码仓库——对供应链敏感的团队请先在隔离环境试用
  • sandbox 默认在 settings.json 里可配置，跑不可信任务前确认沙箱开启
  • workers.json 的 slots 决定并发，本地小模型别开多槽

培训师点评

点评：教 Rig 的重点不是命令，而是它对"Agent 工程化"的回答：长任务进沙箱、定时任务用真实 cron、模型扩能力必须过人审、一切状态落盘可恢复。二进制不分发源码是它目前最大的采用门槛，课堂上必须如实告知学员。

KISS：Rust 写的高性能 Agent Harness——5ms 启动、44 家模型商、子代理/动态 Workflow/浏览器 WASM 全给齐

AI Coding · Agent Harness Show HN；仓库活跃至 2026-09-27 🧪 值得实验 📌 值得收藏 ⭐⭐⭐ 开发者
一句话摘要：受 Pi 启发、用 Rust 重写的终端 Coding Agent：启动约 5ms，内置 44 个模型 provider，支持子代理、定时循环、MCP/ACP 双协议，还能编译成 WASM 在浏览器里跑完整 Agent 循环。

原始教程

  • GitHubracetozero/kiss（README 即完整使用文档；最近提交 2026-09-27）

教程讲了什么

KISS 是一个终端 Coding Agent：默认只有 read/write/edit/bash 四个工具，启动到首帧约 5ms。支持 OpenAI Codex（ChatGPT 订阅）、Anthropic OAuth（Claude 订阅）、Cursor、Google、OpenRouter、Bedrock、GitHub Copilot 等 44 个内置 provider。功能面：会话持久化/恢复/分支/压缩；子代理（最多 4 个活跃子会话、1 层嵌套）；定时循环与 autoresearch；本地/远程 MCP（含 OAuth）；原生 ACP v1（可直接接进 Zed 编辑器）；Rust/Python/TypeScript/WASM 四种 SDK。

关键代码 / 配置

// TypeScript SDK —— 三行起一个 Agent 会话，顺手拿到缓存 token 统计
const session = await Session.create({ tools: ["read", "bash"] })
await session.prompt("What files are here?")
const stats = await session.sessionStats()
console.log(stats.tokens.cacheRead, stats.tokens.cacheWrite)

值得注意的设计：所有 SDK 暴露缓存 token 累计值（cacheRead/cacheWrite/cacheWrite1h），作者明确建议用它做成本看板与告警——这是把"省钱"做成一等 API 的少见案例。

踩坑与注意事项

⚠ 注意：
  • 子代理限制：最多 4 个活跃子会话、仅 1 层嵌套；项目级配置不能开启（安全考虑）
  • ACP 仅支持稳定 v1：Draft v2、音频、旧版 MCP SSE 均不支持
  • 个人项目，迭代极快（9 月下旬几乎每天发版），生产嵌入前锁版本

普通人能不能复现

⭐⭐⭐ 开发者 终端使用对进阶用户友好；SDK/WASM 嵌入面向有工程能力的开发者。

培训师点评

点评：KISS 适合作为"Agent 架构"课的对照样本：四工具默认、协议全开（MCP+ACP）、SDK 四语言、WASM 进浏览器——它证明 Harness 层可以独立于模型厂牌存在。教学时重点带学员读它的限制（4 子代理/1 层嵌套/项目不可开启），限制本身就是安全设计的教材。

用 Exa Agent Ultra 搭一个"深度研究蜂群"：Pydantic 约束子代理，几分钟产出结构化行业数据集

AI Research 发布 2026-09-27 📌 值得收藏 🧩 值得迁移 ⚠ 消耗 API 额度较快，需设预算 ⭐⭐ 有基础用户可复现
一句话摘要：完整 Python 教程：用 Exa 的 subagent swarm API 自动遍历域名层级、解析语义内容，按 Pydantic schema 产出可直接喂给 RAG 的结构化公司数据集。

原始教程

  • Blog 教程CogitoDaily — How to Build Deep Research Swarms with Exa（作者 Alfian Majid，2026-09-27）

教程讲了什么

教程从零建一个 exa_swarm_demo 项目：用 AsyncExa 客户端触发 Agent Ultra 蜂群搜索，根控制器把查询拆成多个子查询，每个子代理执行"语义发现 → 深度递归遍历 → schema 对齐抽取"三段式流程；用 Pydantic v2 定义 EnterpriseTarget/ResearchSwarmResult 强约束输出；10 个子代理并行绘制"2026 年向量数据库与检索中间件市场地图"，结果进 pandas 导出 CSV。

关键代码 / 配置

response = await exa.agent_ultra_search(
    query=prompt,
    num_subagents=max_subagents,
    depth="exhaustive",
    output_schema=EnterpriseTarget.model_json_schema(),
    filter_domains=["github.com", "medium.com"],
    crawl_subpages=True,
    max_depth_per_site=2
)

整篇教程的核心思想就一句：用 schema 而不是 prompt 来约束蜂群。output_schema 直接传 model_json_schema()，抽取模型对着它解析原始 HTML，丢弃导航栏/页脚/cookie 横幅等噪声。

踩坑与注意事项

⚠ 原文给出的三类高频故障：
  • ExaSubagentTimeoutException（120s 超时）→ 把 max_depth_per_site 从 3 降到 1–2
  • pydantic.ValidationError: website_url → 把 HttpUrl 换成 str + 自定义校验器自动补 https://
  • ExaQuotaExceededError → 别写宽泛查询；用 include_domains 收窄 + 测试期 num_subagents=4

培训师点评

点评：这篇教程最该教的是"schema 先行"的研究工程观：先定义你要的字段，再让蜂群去填满它，校验失败的宁可丢弃。这比"让 AI 写份研究报告"高一个段位——产出是可复用的数据资产而非一次性文本。务必提醒学员：先设预算再开蜂群。

不开剪辑软件做动画视频：Claude Code 写 HTML 逐帧 + FFmpeg 合成，600 帧 20.6 秒导出

AI Creator 原帖 2026-09-26 🔥 值得马上实践 ⚠ 二手整理（基于作者一手帖） ⭐⭐ 有基础用户可复现
一句话摘要：一位非工程师用 Claude Code + HyperFrames 技能包 + FFmpeg，把 20 秒 1080p 动态图形视频做成"写网页"：600 帧网页截图逐帧渲染，再拼成 2MB MP4，改时间只改一个数字。

原始教程

教程讲了什么

传统 Browser Agent 让大模型"写下一步操作"，容易产生选择器幻觉；fast-browser-use 换了一条路：先读取渲染完成的 DOM，把当前真实可见、可操作的元素整理成一组带编号的合法候选动作，映射为 token，模型只做一次前向计算对候选集打分，选出下一步。开放问题被收窄成"从已存在的选项里选一个"，从机制上消灭幻觉。

关键设计

最值得抄的不是代码而是动作空间收窄：模型永远只能选"当前真实存在的元素"，非法选择器在候选集构造阶段就被物理排除。社区总结的判断原则同样值得记：完全确定性任务用正则/代码；模糊输入但有界输出用决策模型；开放式生成推理才用 LLM。

  • 决策模型输出的是概率不是事实：安全关键场景必须人工/规则兜底
  • "感知→结构化"这半步决定成败：喂给决策模型的页面状态质量，一半靠你自己的 DOM 治理
  • 它不会写材料、不能看视频、不做开放推理——别把决策节点当大脑用
