01

用 Python + FastMCP 给禅道写一个 MCP 服务，让 Agent 替你看 Bug

MCP 实战🔥 值得马上实践🧑‍💻 开发者向🧩 值得迁移2026-09-29 发布
用不到 40 行 Python 手写一个禅道 MCP 服务，接入 Cursor 后对 AI 说一句"帮我看看 Bug #1024"，Agent 就能查详情、列清单、改任务状态。

原始资料

  • 原文让 Agent 替你看 Bug：简单示例读懂 MCP 服务（掘金）
  • 依赖MCP 官方 Python SDK（FastMCP 所在包）

教程讲了什么

禅道是国内团队用得最多的缺陷管理系统，但 Coding Agent 天生访问不了它。作者用一个最小例子讲透 MCP 服务本质：MCP 就是一个独立进程，Agent 通过 stdio 发 JSON-RPC 请求，你的服务去调禅道 REST API，把结果格式化成纯文本返回。教程从单个 Tool（zentao_get_bug）跑通，再扩展到列表查询、任务状态更新，最后总结四条 MCP Tool 设计原则：按意图拆分 Tool、docstring 写触发场景、只把真正必填的放 required、返回纯文本不返回 JSON。

技术栈

模型不绑定具体模型，通过 Cursor 等 MCP 客户端调用其内置模型
工具Python、FastMCP（mcp 官方 SDK）、Cursor（MCP Host）
API禅道 REST API（15.0+，需管理员开启）
部署本地 stdio 进程，Cursor 自动拉起

为什么值得收藏

目前少见的"从零到接入 IDE 全链路、代码可直接复制"的中文 MCP 实战教程。最大价值不在代码量，而在四条 Tool 设计原则——这些是决定 Agent 选 Tool 准不准的实战经验，可直接迁移到任何内部系统（Jira、飞书、钉钉、内部 Wiki）。

培训师点评：真正值得教的是四条 Tool 设计原则——它们把"MCP 怎么写"升级为"Agent 怎么用好"。这是把概念课变成工程课的分水岭，建议作为 MCP 系列课程的第一讲。

隔离内网下的 AI Agent 工程实战：给所有内网系统统一装上 MCP + 审批 + 留痕

MCP 企业治理📌 值得收藏🏢 企业向🧩 值得迁移2026-09-29 发布
一位一线工程师复盘公司内部落地 internal-mcp 的完整架构：内网系统统一封装 MCP Tools，写操作走人工审批，每次调用留痕——国内少见的"AI 进企业内网"治理方案。

原始资料

  • 原文掘金内网 MCP 网关实战复盘（一线工程师第一手记录）

教程讲了什么

文章给出完整的企业内网 MCP 治理架构：读操作（查 Bug、查日志、查监控）直接放行；写操作（改任务状态、发通知、改配置）必须先生成"待执行单"，经人工审批后才真正调用；所有调用落审计日志，含调用者、时间、参数、审批人。凭据统一由网关托管，Agent 不直接接触数据库密码。这是国内少有的把"AI 改了内网数据谁负责"这个问题正面回答的工程方案。

核心设计

  • 读/写分离：读 Tool 直接执行，写 Tool 强制审批。
  • 待执行单模式：Agent 生成 diff/动作描述，人在审批页点确认才落地。
  • 凭据托管：内网系统密钥存网关，Agent 只拿短期 token。
  • 全量留痕：每次调用入审计库，可回溯、可举报。
培训师点评：这是昨天最值得企业培训引用的中文一手材料——它把"Agent 治理"从 PPT 概念落成了可抄的领域模型。教它的重点不是代码，而是"写操作先落待执行单"这个治理思想。

Browser Use Cloud v3 BU Agent API 实战：用几行代码把浏览器任务变成"任务进、结果出"

Browser Use🔥 值得马上实践🧑‍💻 开发者向2026-09-29 发布
系统讲解 Browser Use Cloud 实验性 v3 Agent API：认证、SDK、run() 执行模型、16 个 REST 端点（会话/消息/文件/工作区）、成本控制与错误处理，读完就能用代码提交一个浏览器自动化任务。

教程讲了什么

v3 把"本地跑浏览器 Agent"变成了云 API：你 POST 一个自然语言任务，它返回 run_id，异步执行完再回调结果。教程覆盖认证、SDK 初始化、run() 执行模型、16 个 REST 端点（会话/消息/文件/工作区）、成本护栏（max_steps、timeout）、错误重试与资源收尾。特别强调 live_url 参数——提交任务后可以实时看到 Agent 在浏览器里做什么，这是调试 Browser Agent 最快的方式。

踩坑：① 不设 max_steps 容易空转烧钱；② 任务结束务必显式释放工作区，否则云资源持续计费；③ 用 live_url 调试，不要盲调。
培训师点评：值得教的是"成本护栏 + 资源收尾"这套工程习惯，而不只是调 API。教学时务必用 live_url 让学员亲眼看到 Agent 在浏览器里做什么——这是理解 Browser Agent 最快的方式。

GitHub Agentic Workflows v0.90.0 发布：用自然语言在 Actions 里编排 Agent，还能给轨迹打分

Agent 工作流📌 值得收藏🏢 工程指标2026-09-29 发布
GitHub 官方 gh-aw 发布 v0.90.0：step summary 显示 friction cost、空任务零积分退出（noop）、五个新轨迹评分器——把"Agent 干活干得值不值"变成了可度量的工程指标。

教程讲了什么

gh-aw（GitHub Agentic Workflows）是 GitHub 官方把 LLM Agent 接进 Actions 的项目。v0.90.0 三个重点：① step summary 里直接显示 friction cost（每一步花了多少 token/钱）；② 空任务 noop 零积分退出，Agent 判断没事可做就不烧钱；③ 五个新 trajectory graders（轨迹评分器），从正确性、完整性、安全性、效率、可复现性五个维度给 Agent 的一次执行打分。这意味着"Agent 自动化"第一次有了和 CI 一样可度量的质量门。

培训师点评：这版更新的教学价值在指标思维：任何团队上 Agent 自动化前，先回答"空转成本、总成本、质量分"三个问题——gh-aw 恰好把答案产品化了。

WeKnora 的差异化在"自维护"：传统知识库是项目制——一次性灌入文档就不再动；WeKnora 让 Agent 在回答用户问题时，自动把新产生的知识（FAQ、踩坑、新结论）沉淀回 Wiki，并经人工审核后入库。知识库从"静态文档"变成"随问答生长的运营资产"。核心风险也在这里：自动沉淀如果没有审核流，就是自动污染。
